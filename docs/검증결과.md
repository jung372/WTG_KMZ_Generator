# 로컬 시험판 검증 결과

버전 0.1.0 / 프리셋 e175-concept-1 / 검증일 2026-11-02.

## 통과한 검사

- TypeScript 정적 타입 검사와 production 렌더러·main·preload 빌드.
- Vitest 25개 시험: 좌표 경계·오류, 각도 정규화, 치수·3엽 간격, H/D 독립 조정, 방위, 고도, DAE 정점·참조 재해석, XML 이스케이프, ZIP 재현성, 파일명, IPC 데이터 검증, 실제 디스크 덮어쓰기·실패 시 보존.
- 개발 런타임의 실제 Electron 창: WebGL 미리보기·Worker·격리 API, 한글/공백 경로 KMZ 쓰기, 취소·재시도, 낡은 입력 저장 차단, 재생성 후 H150·풍향90 출력, 오류 좌표 차단, 지면 아래 로터 확인, 도움말·작은 화면.
- 공식 OGC KML 2.2 XSD 검사 및 DAE XML·참조 검사. DAE 전체 XSD 검사는 미실행.
- 화면 캡처를 열어 기본·작은 화면의 글자·입력·3D·저장 버튼 표시 확인.
- `npm audit --omit=dev`: 실행 의존성에 보고된 취약점 0건. 전체 개발 트리에는 electron-builder의 전이 minimatch 등 moderate 15건이 보고됨. 파괴적인 자동 다운그레이드는 적용하지 않음.

환경: Windows x64, Electron 45.2.1 / 내장 Chromium 156.0.8078.75. OS 세부 빌드는 release-manifest.json 참조. 개발 Node.js 22.23.1. 모델 5,384 triangles, 대표 KMZ 약 126KB. 화면의 생성 시간은 참고 실측이며 원문의 T16 전체 성능 인수를 대체하지 않음.

## 시험 방법의 범위

UI 자동 시험은 Windows 저장 대화상자의 선택 결과만 대체하고 실제 preload·main IPC 검증 및 파일 쓰기를 수행했다. 사람이 대화상자를 직접 조작한 인수 시험과는 구분한다. 좌표·모델 네트워크 전송은 없고, 앱의 세션·CSP에서 원격 요청을 차단한다.

최종 `program/win-unpacked/WTG KMZ Generator.exe`에서 전체 UI 스모크 시험을 통과했다. `test-results/packaged-body-report.json`과 `smoke-report.json`, `app-preview.png`, `app-compact.png`, 생성 KMZ가 증빙이다. 보고서의 실행 대상은 최종 본체 EXE다. 별도의 단일 Portable EXE는 자동화 연결과 일반 Start-Process 모두 Windows 접근 거부가 발생했으므로 본체 검증과 구분한다. Setup EXE 설치·제거 시험도 미실행이다.

최종 본체에서 H120·D175를 10회 다시 생성한 Worker 형상+KMZ 시간은 0.21~0.29초, nearest-rank p95는 0.29초다. 화면의 0.01초 단위 표시값이며 프리뷰 첫 프레임·디스크 저장 시간은 제외했다. CPU는 AMD Ryzen 5 PRO 6650U, 논리 CPU 12개, OS가 보고한 RAM 약 15GiB, Windows 11 Enterprise 10.0.26300이다. 이 부분 실측으로 T16 전체 인수를 주장하지 않는다.

단일 Portable 실행 시도 이후 파일 읽기에서도 EPERM이 관측되었다. 읽을 수 없는 포장 파일은 manifest에 해당 상태와 null 체크섬을 기록하며 SHA256SUMS에 포함하지 않는다. 사용 가능한 폴더 ZIP과 실행 확인한 본체는 별도로 해시를 생성한다. Windows 정책의 구체적인 원인은 확정하지 못했다.

전달용 `program/WTG-KMZ-Generator-Folder-0.1.0-x64.zip`은 전체 ZIP CRC 검사, 필수 main·preload·HTML·EXE 존재, 경로 이탈 없음, 압축 안 런타임의 SHA-256과 공식 원본 일치를 확인했다. 증빙은 `test-results/folder-zip-report.json`이다. 사용 안내를 포함하며 압축을 전부 풀고 EXE를 실행하는 방식이다.

## 빌드 환경 문제와 처리

기본 제한 환경에서 Vite 하위 프로세스의 spawn EPERM이 발생하여 동일 검사를 허용된 실행 환경에서 다시 실행했다.

NSIS 설치 패키징은 빌드용 임시 EXE를 실행해 제거 프로그램을 쓰는 단계에서 EPERM이 반복되었다. 시스템 보안을 끄지 않고 electron-builder 자체의 UninstallerReader로 제거 프로그램을 추출하도록 `scripts/build-windows.mjs`에 버전 한정 어댑터를 작성했다. 의존성 원본 파일은 수정하지 않았다.

초기 리소스 편집 빌드의 본체 EXE에서 읽기·실행 접근 거부가 관측되었다. ACL 비교에서 차이는 확인하지 못했고 보안 탐지 원인은 확정하지 못했다. 같은 앱에 원본 Electron EXE를 그대로 복사해 실행하면 실제 창·3D·KMZ 준비가 정상 표시되었다. 이를 근거로 최종 로컬 빌드는 `asar: false`, `signAndEditExecutable: false`로 런타임 EXE의 바이트를 변경하지 않고 `program/`에 생성한다. Windows 파일 속성의 제품명·아이콘은 Electron 기본 표시가 남을 수 있다. 앱 내부 버전·KMZ 속성·manifest로 제품 버전을 확인한다. 이전 `release/`·`release-local/`는 중간 빌드이며 배포 대상으로 사용하지 않는다.

## 아직 인수하지 않은 항목

- 다른 물리 PC·새 Windows 프로필에서의 최초 실행·설치·제거·업데이트와 portable 전달.
- 실제 Google Earth Pro 정면·측면·사선 외관, 네 방위, 평지·산지 배치 및 다른 PC 파일 이동. 로컬 설치 존재는 확인했으나 앱의 실제 표시를 검증한 것으로 간주하지 않음.
- T16 기준 환경 10회 p95·조작 fps·메모리 누수와 DPI 150%·200% 실측.
- 디스크 부족·이동식 디스크 분리·모든 종류의 파일 잠금·앱 강제 종료 등 전체 장애 주입.
- 제조사 공식 E2 상세 치수·각도·기종 표기 확정, 공차 기반 외관 수용.
- 코드 서명·타임스탬프·다른 PC의 SmartScreen·백신 정책 검증.

이 결과는 로컬 시험판의 확인 범위다. 원문 T01~T16과 D01~D10 전체가 통과한 정식 출시로 표시하지 않는다.
